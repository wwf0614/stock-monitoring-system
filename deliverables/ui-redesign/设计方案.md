## 二、信息架构：从 3 视图改为 4 视图

现有 `dashboard.html` 是 3 个 view，问题在于**"下一步投资方向"埋在第 3 屏**，而这是你最需要的结论。

| 现有 | 新方案 | 变化 |
|---|---|---|
| 0 持仓（总值 → 基金表单+表格 → 盘面总览） | **持仓** | 表单收进右下角 `+` 浮动按钮，首屏不再被输入框占据 |
| — | **决策**（新，独立成页） | 仓位区间、五维评分、调仓建议、下一步方向 |
| 1 研判 + 资金（挤在一页） | **资金** | 拆开，专注板块轮动与主力流向 |
| 2 市场行情 | **市场** | 保留，指数卡 + 涨跌家数 + 消息面 |

手机用底部标签栏切换，桌面（≥1024px）自动切为左侧导航栏。

## 三、设计系统

### 色彩 — 关键决策：品牌色必须避开红/绿

红绿已被"涨/跌"语义完全占用，**任何品牌色再用红绿都会造成误读**。因此：

```
强调色  冷青蓝 #56c7ee   仅用于：选中态、主按钮、焦点环、活动指示（用量 < 10%）
涨      #f2565d          跌  #2ecfa2       警示 #f0b357
中性层  #0d1015 → #131820 → #191f28 → #202834（深灰带微冷蓝调，不用纯黑）
```

深色靠**表面亮度分层**，不靠阴影堆叠——这是终端感和"卡片套卡片"的分界线。

### 字体

```
数字/大标题  Bahnschrift（Win 自带，DIN 风几何体）→ 数据一律 tabular-nums 对齐
中文界面     PingFang SC / 鸿蒙 / MiSans / 微软雅黑
```

数字用 DIN 风是这套界面最明显的识别点——大金额、涨跌幅全部等宽对齐，竖着扫一眼就能比大小。

### 字号与间距

- 5 级固定字号（11 / 13 / 14 / 16 / 20px + 流体 hero），中文正文 14px 起
- 4pt 间距基线：4 / 8 / 12 / 16 / 20 / 24 / 32
- 深色下正文行高 1.6（浅色上加 0.05–0.1 补偿视觉重量）

## 四、四个关键界面决策

### 1. 首屏 = 持仓盈亏（你的选择）

Hero 卡：总市值用 `clamp(2.4rem, 10vw, 3.4rem)` 流体大数字，下方三个并排指标（今日浮动 / 持有收益 / 投入本金），右侧一条 40 日净值 sparkline（内联 SVG 手绘，不引图表库）。

底部「主题敞口」条替代原来的"权益/防御"二分——你 4 只全是权益类，二分没有信息量；按 **AI算力 / 半导体 / PCB / 创新药** 拆才能看出集中度风险（当前半导体+算力占 69%，这个信号很重要）。

### 2. 决策条：结论优先（差异化记忆点）

紧随 Hero 之后一条高对比条，给**唯一结论 + 唯一理由 + 费率护栏**：

```
→ 持有不动 · 建议仓位 40%–55%，当前 47%
  主力小幅净流出 12.4 亿，但持仓所在概念仍净流入。已满 36 天、赎回费为 0，
  此时调仓没有费率损失——但也没有必须动的信号。
  [✓ 赎回费 0%（已满 30 天）] [主力 −12.4 亿] [情绪 中性偏弱]
```

左侧 3px 竖条 + 字形图标作强调，不用大色块刷存在感。

### 3. 持仓：卡片式，手机不用横表格

手机端表格要横向滚动、难读。改为卡片：

- 左：名称 / 代码 / 持有天数 / 概念标签（最多 4 个，超出折叠 `+N`）
- 右：今日估算涨幅（大）→ 市值 → 持有收益
- 底：概念资金净流入 + 「详情」展开
- 展开层：数据来源、本金、赎回费、持有进度条（X / 30 天）、完整概念敞口

### 4. 费率护栏：写进每一处可能触发操作的地方

你的核心约束是"持有 <7 日赎回费 ≥1.5%、C 类满 30 日免赎回费"。设计上让它**不可忽略**：

- 决策条的 guard 标签区
- 持仓卡展开的「赎回费」字段（满 30 天显示绿色 `0%`，未满显示琥珀色具体费率）
- 决策页调仓建议整块挂 `已含赎回费约束` 标签
- 持有进度条可视化 `36 / 30 天`

## 五、响应式

移动优先，`min-width` 逐层增强：

| 断点 | 变化 |
|---|---|
| 默认（手机） | 单列、底部标签栏、`+` 浮动按钮、底部抽屉表单、安全区适配（刘海/ home 指示条） |
| ≥640px | 持仓卡双列、展开详情三列 |

## 六、动效（克制，只服务状态变化）

- 数字刷新时**按方向闪一次**（涨红 / 跌绿），0.5s 指数缓动 —— 盯盘场景最能感知变化的细节
- 刷新按钮图标旋转 0.8s
- 视图切换 8px 上移淡入（0.34s `cubic-bezier(.22,1,.36,1)`）
- 抽屉 0.36s 缓出，scrim 模糊
- 不用回弹/弹性缓动，不做装饰性动画

## 七、接入真实数据的落地清单

原型用的是拟真数据，字段名已对齐现有接口。接 `server.py` 时：

1. **持仓页** ← `GET /api/fund_quotes`
   - `rows[]`: `name / code / amount / market_value / pct / hold_pct / hold_pnl / concepts / nav_date`
   - 汇总: `total_market_value / total_amount / total_hold_pnl / last_sync`
   - ⚠️ **缺失字段**：`hold_days`（持有天数）—— 可由 `buy_date` 现算，前端加个 `daysBetween(buy_date, today)` 即可，不用改后端

2. **决策页** ← `GET /api/board_analysis`
   - `regime / regime_label / confidence / scores / recommendation / fund_advice / next_step / market_trend`
   - 现有已全，直接映射

3. **资金页** ← `GET /api/capital_rotation`
   - `capital.sector_flow_in/out / concept_flow_in/out / breadth / money_flow`，`rotation`
   - ⚠️ 涨跌家数 `breadth` 已有，可直接用

4. **市场页** ← `GET /api/snapshot` + `GET /api/index_kline`
   - 指数卡用 `snapshot.indices`；sparkline 用 `index_kline.series[].points`
   - 新闻用 `snapshot` 里的 `news`

5. **主题敞口条** ← 需要新逻辑
   - 现有 `concepts` 是逐只基金的概念列表，没有"主题归类"
   - 方案：在 `fund_manager.py` 加 `THEME_MAP`，把概念映射到 4–5 个主题桶（AI算力/半导体/PCB/创新药/其他），前端按桶聚合市值
   - 这是唯一需要改后端的地方

6. **保留**：token 网关鉴权、5s/15s 双通道刷新节奏、免责声明
