# 预测命中率记录与校准系统

搭建日期：2026-09-03

## 为什么要做

量化研判输出的「置信度」是启发式打分，不是真实概率。没有事后回填，谁也不知道它到底准不准——看到的只是一个好看的数字。

本系统把「预测 → 事后 → 校准」闭环起来：**让系统自己告诉你它有多准**，以及**哪一个置信度档位是自我高估的**。

核心认知：A股次日方向预测的准确率上限约 55%，「更准的预测」是伪目标。真正有价值的是知道模型的偏误在哪，以及哪些结论可以照单全收、哪些要打折扣。

## 数据流

```
forecast.forecast_market()
   ↓ 产出研判时，连同当时的指数点位(锚点)一起落盘
forecast_history.json
   ↓ 次日收盘后，用「锚点 → 次日收盘」算真实涨跌
   判定 命中 / 部分 / 落空
   ↓
build_stats() → /api/forecast_stats → 看板「模型实测」卡片
```

## 文件

| 文件 | 作用 |
|---|---|
| `forecast_track.py` | 核心模块：记录 / 回填 / 统计 |

## 记录规则

- **按 (锚点日期, lookback) 去重**：前端反复刷新不会刷出重复样本。同一天同一窗口只保留最新研判。
- **另存当日首次快照 `open`**：可对比「早盘研判 vs 收盘前研判」哪个更准。
- **值未变化 + 120 秒内 → 节流不写盘**，避免高频 IO。
- 记录失败绝不影响研判主流程（静默返回 False）。

## 判定规则

阈值 `±0.30%` 作为平盘带（A股主要指数日波动标准差约 1%，不能用 0.01% 的噪声当方向）：

| 预测 | 实际 | 结果 |
|---|---|---|
| 看多 | ≥ +0.30% | 命中 (1.0) |
| 看多 | −0.30% ~ +0.30% | 部分 (0.5) |
| 看多 | ≤ −0.30% | 落空 (0.0)；≤ −1.0% 标记「反向」 |
| 看平 | \|涨跌\| ≤ 0.50% | 命中；≤ 1.20% 部分；否则落空 |

**半命中（0.5）的设计意图**：样本少时，避免被阈值边界的噪声主导判断。

## 统计指标怎么读

- **实测命中率**：加权（含半命中）。严格命中率只算 1.0。**< 45% 说明模型不如抛硬币，> 55% 才有实用价值**。
- **Brier 评分**：把置信度当方向概率，与真实涨跌二元结果比对。**0.25 = 「永远猜 50%」的基准线**，低于它才说明置信度含真实信息。
- **置信度校准**：竖线 = 模型自称的把握，色条 = 实际命中率。色条明显短于竖线 → 该档位在自我高估，不要照单全收。
- **仓位建议有效性**：按建议仓位中位数分成高/低两组，比较次日实际收益。低仓位组次日明显更差 → 波动率目标仓位在择时上有效。
- **时点对比**：当日首次研判 vs 最终研判的命中率，回答「早上看还是收盘前看更准」。

**样本 < 20 次时，看板只显示「已记录 N 次、待回填 M 次」，不显示任何命中率数字**——几条样本算出来的准确率是噪声，不是结论。

## 踩过的坑

- **清空历史必须连 `.bak` 一起删**：`json_util.safe_load_json` 在主文件缺失时会回退到 `.bak`，只删主文件历史会「复活」。已提供 `reset_history()` 处理。
- **主指数必须显式挑选**：`forecast` 返回的 `indices` 数组顺序不保证，事后检验要固定用沪深300（与 `_build_view` 的 core 选择一致），否则锚点会在指数间跳变。
- **锚点用「预测时的最新 K 线收盘价」**：盘中发出预测时锚点可能是当日实时价，回填时取「日期严格晚于锚点」的第一根 K 线即可，天然得到「从预测发出到次日收盘」的真实收益。
